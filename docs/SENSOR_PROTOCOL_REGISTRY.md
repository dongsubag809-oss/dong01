갱신: 2026-11-09 / V5.12. 이전 추정 맵보다 사용자가 제공한 아래 문서를 우선 적용한다.

- SHA256: b23252c2dc08f70191e9638ebc47ccd0272103fb2146be1612b29e6d82f0054d
- 근거 절: 3.2 배선, 4.2 전원 재인가, 5.1/5.2 기본 통신, 5.4~5.7 레지스터/변환/설정 예.

## 확정 문서 정의

| 항목 | 정의 |
|---|---|
| 인터페이스 | RS485, Modbus RTU |
| 기본값 | ID1, 9600bps, 8N1(패리티 없음) |
| 지원 속도 | 2400 / 4800 / 9600bps |
| 습도 | FC03, 0x0000, unsigned16, ÷10 %RH |
| 온도 | FC03, 0x0001, signed16 2의 보수, ÷10 °C |
| 바이트 순서 | 레지스터 상위 바이트 먼저; CRC 하위 바이트 먼저 |
| ID 쓰기 | FC06, 0x0100(256), 데이터=새 ID |
| 속도 쓰기 | FC06, 0x0101(257), 데이터 0=2400 / 1=4800 / 2=9600 |
| 적용 시점 | ID/속도 변경 후 센서 전원을 껐다 켜야 적용 |
| 읽기 예 | 01 03 00 00 00 02 C4 0B |
| ID1→2 예 | 01 06 01 00 00 02 09 F7 |
| 속도→9600 예 | 01 06 01 01 00 02 58 37 |
| 배선 | 빨강=전원+, 검정=전원-, 노랑=485 A, 초록=485 B |
| 전원 | DC12~24V |

문서의 주소 허용 범위는 절마다 0~255 또는 01~251로 다르다. 프로그램은 Modbus 일반 유니캐스트 범위 1~247만 사용하고, 등록 ID는 사용자 지시대로 1~5로 고정한다. 브로드캐스트 설정은 하지 않는다. 패리티 설정 레지스터는 제공되지 않아 8N1로 고정한다.

### 문서 오기와 실제 검증값

5.5 응답 예시는 `01 03 04 00 92 FF 9B 5A 3D`로 적혔으나 이 데이터의 CRC는 `5B 85`다. 습도 계산 설명 0x0292(658=65.8%)를 적용한 `01 03 04 02 92 FF 9B 5A 3D`가 CRC와 일치한다. 프로그램은 실제 수신 데이터 전체의 CRC를 계산하며 오기 프레임을 허용하지 않는다. FF9B는 signed16 -101, ÷10=-10.1°C로 검증했다.

## 환경 설정: ID와 동 번호 고정

| 센서 ID | 저장·표시 대상 | 기본 속도 |
|---|---|---|
| 1 | 1동 내부 온습도 | 9600bps |
| 2 | 2동 내부 온습도 | 9600bps |
| 3 | 3동 내부 온습도 | 9600bps |
| 4 | 4동 내부 온습도 | 9600bps |
| 5 | 5동 내부 온습도 | 9600bps |

- COM6에서 별도 작업 스레드와 전용 네이티브 fd로 5개 ID를 순서대로 조회한다. COM5 PLC ID1/2와 센서 ID1/2는 서로 다른 포트다.
- V5.09의 저장 경로·속도는 이관하고, 등록 ID는 1~5동 번호에 고정한다. 새 기본 설정은 모두 /dev/ttyS6 후보 경로·9600bps·8N1이다.
- COM6 외부 명칭과 Linux 경로의 대응은 현물 미검증이다. /dev/ttyS6를 확정 경로로 주장하지 않으며, 실제 장치 목록에서 변경 가능하다.
- 실제 응답이 없는 동은 미수신이며 다른 동 데이터/설정값/가상값을 복사하지 않는다.
- 실제 CRC 수신값은 해당 동 현재값 및 일·주·월 SQLite 이력에 연결된다. 366일 보관과 공백 처리를 유지한다.
- 속도는 센서별로 등록할 수 있다. 같은 버스에서는 모두 9600bps로 통일하는 구성을 권장하며, 마스터는 등록 속도에 맞춰 순차 조회한다.

## 새 센서 설치·변경 순서 (V5.12 간편 화면)

1. 환경 모니터링에서 센서 연결·ID 설정을 누르고 1~5동 버튼을 선택한다. 선택 동 번호가 목표 ID다.
2. 선택 동에 센서 연결 / 변경을 누른다. 다른 센서를 분리하고 설정할 센서 한 대만 연결한 뒤 확인 항목을 체크한다.
3. 센서 찾기는 기존 읽기 검색으로 현재 ID/속도를 찾는다. 이미 정상 수신되면 검색을 생략할 수 있다.
4. 해당 동으로 설정을 누른다. 현재 ID가 같으면 FC06 없이 기존 수신 설정 저장과 실제 수신 2회로 자동 등록한다. ID가 다르면 기존 단일 ID 쓰기 절차를 사용한다.
5. 전원 재인가 안내 후 실제 센서 전원을 껐다 켠다. 새 ID/속도 CRC 정상 응답 2회 후 대시보드·이력 자동 연결과 전체 감시 재개. 보류 중에는 다시 쓰지 않는다.
6. 속도/장치 경로/수신맵/수동 확인/복구/OLED/송수신 진단은 접힌 고급 설정에서 사용한다. 속도 변경은 현재 ID·속도로 수정 시작 후 한 대 연결 확인을 다시 체크한다.
7. 설정 모드에서 동 선택을 잠가 목표가 바뀌지 않게 한다. 임시 ID의 수신값은 어느 동의 이력에도 넣지 않는다. 실제 수신이 없으면 미수신으로 표시한다.

## 쓰기 및 복구 기준

- FC06은 제공 문서의 0x0100/0x0101 두 레지스터만 Java와 C 양쪽에서 허용한다. 다른 센서 레지스터/PLC DO 쓰기는 허용하지 않는다.
- 각 변경 전에 현재 장비를 다시 읽고, 변경 대기 정보를 동기식 영구 저장한 뒤 명령을 정확히 한 번 전송한다.
- 응답 누락/CRC 오류/Modbus 예외/앱 재시작 시 재전송하지 않는다. 저장된 보류 상태에서 전원 재인가 후 새 설정의 실제 응답으로 확인한다.
- 새 설정 응답이 없고 기존 설정에서만 실제 응답하면 기존 응답 설정으로 복구 가능하다. 복구도 읽기 재확인 후 등록만 변경하며 FC06을 추가 송신하지 않는다.
- 보류 중에는 다른 쓰기/등록 설정 변경을 차단한다. 센서 전원 차단은 프로그램이 대신 실행하지 않는다.
- 이전 조사에서 비교한 타 제조사의 ID0x0002/0x07D0 맵은 이 센서에 사용하지 않는다.

## V5.11 수정 및 현장 확인 한계

- V5.10은 새 ID 수신 확인 후에도 setup/registered=false 상태를 유지하여 등록 버튼을 추가로 누르지 않으면 대시보드·이력을 차단했다. ID2 모의 사례로 확인한 코드상의 문제이며 사용자의 실제 장비 상태를 원격 조회한 결과는 아니다.
- 보류 변경은 새 ID/속도 읽기만 주기적으로 수행하고 2회 정상 응답 후 자동 등록한다. FC06 쓰기를 재전송하지 않는다. 이전 버전의 등록 대기도 실제 응답 확인 후 복구한다.
- 일반 감시의 TX/RX/오류는 선택 동의 기록을 표시한다. 누락된 다른 ID의 마지막 오류를 선택 ID2의 오류로 표시하지 않는다.
- 초기화 전 nativeMessage 알림을 바로 호출하던 흐름을 문서 준비 후 큐 전달로 변경했다. 모듈 초기화는 분리하고 오류에는 파일/행/열/스택 및 Android 콘솔 정보를 표시한다. 현장 Script error.(행0)의 정확한 예외는 해당 메시지만으로 확정할 수 없으므로 실제 Android WebView 시험을 함께 수행한다.
- Java bridge 메서드 호출은 Function.apply에 의존하지 않는 직접 호출로 변경했다. 이 변경 자체를 현장 오류의 확정 원인으로 주장하지 않는다.
- 기존 COM5 C/Java 드라이버, 센서 레지스터/배율/ID쓰기 제한, DO·정역 인터록 및 휴대폰 게이트웨이는 유지한다. 실제 HMI와 센서의 전원 재인가/수신은 현장 미검증이다.

## V5.12 메뉴 간소화 및 리뷰 범위

- 기본 화면은 동 선택 버튼, 센서 확인, 동 번호로 적용, 전원 재인가 안내만 순서에 맞춰 표시한다. 고급 통신 기능은 삭제하지 않고 접힌 메뉴로 이동한다.
- UI만 변경하며 SensorController/Protocol/Serial의 Java/C, COM5 PLC, DO 주소, 인터록과 휴대폰 게이트웨이 코드는 V5.11과 동일하다.
- 같은 ID의 연결은 기존 configureSensor의 2회 실수신 자동 등록을 사용한다. 설정 버튼을 누른 상태를 측정값 또는 수신 완료로 표시하지 않는다.
- 단일 센서 확인 전 설정 차단, 설정 중 동 전환 차단, 보류 변경 재전송 차단, 검색 취소와 수신 끊김 표시를 검증한다. Android 7.1 WebView에서 800×600 / 1024×600의 기본·설정·전원 대기·고급 화면 배치를 배포 전 검사한다. 실제 HMI와 RS485 현물은 미검증이다.
